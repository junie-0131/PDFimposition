# ShiftMax 勤怠自動打刻

ShiftMax（勤怠報告一覧）の「出発 / 上番 / 下番」リンクを、指定の許容時間内に自動で押す仕組み。

## 構成
- `punch.mjs` … 一覧ページを読み、対象リンクと表示時刻を解析し、許容時間内なら打刻する Node スクリプト（依存なし・要 `curl`）。

## スクリプトの使い方
```bash
SHIFTMAX_URL='<便利URL WorkTimeListForStaff.aspx>' \
node punch.mjs --action 出発 --expect 08:30 --window 06:30-07:29 [--dry-run]
```
- `--action` 押す対象（出発 / 上番 / 下番）
- `--expect` その行に表示される時刻（例 08:30）。パターン取り違え防止用。
- `--window` 押してよい許容範囲（JST, `HH:MM-HH:MM`）。範囲外なら**絶対に押さない**。
- `--dry-run` 実際には押さず、判定結果だけ出力。
- `--safety-sec` 終端手前の安全マージン秒（既定20秒）。

### 結果(RESULT)
| RESULT | 意味 |
|---|---|
| SUCCESS | 打刻して「◯◯報告完了」を確認 |
| SKIP_NO_MATCH | 対象リンクなし（休み/打刻済み/別パターン）→ 何もしない |
| SKIP_OUT_OF_WINDOW | 許容範囲外 → 誤打刻回避のため押さない（要手動） |
| SESSION_EXPIRED | 便利URLの有効期限切れの可能性 |
| ERROR / UNCERTAIN | 通信失敗など → 要手動確認 |

## 打刻ルール
勤務は不定期（水曜・祝日は無し。毎月シフト割当）。毎朝ページを読み、勤務日なら A/B いずれかのパターンになる。

全操作が**タイムアウト式**。トリガーはまず `--dry-run` で対象日か判定し、対象ならその旨を本人に通知して
締切時刻まで待機する。締切までに本人から見送り指示（「休み」「残業」など）が届けば押さず、
届かなければそのまま打刻する。対象日でなければ通知も打刻もしない。

### Aパターン（出発・上番の表示が 08:30）
| 操作 | 許容範囲(JST) | 通知 → 自動打刻 |
|---|---|---|
| 出発 | 06:30–07:29 | 06:42 通知 → 07:10 打刻 |
| 上番 | 08:15–08:29 | 08:05 通知 → 08:22 打刻 |
| 下番 | 17:15–17:29 | 17:14 通知 → 17:25 打刻（残業なら見送り） |

### Bパターン（出発・上番の表示が 15:00）
| 操作 | 許容範囲(JST) | 通知 → 自動打刻 |
|---|---|---|
| 出発 | 13:45–13:59 | 13:30 通知 → 13:52 打刻 |
| 上番 | 14:45–14:59 | 14:30 通知 → 14:52 打刻 |
| 下番 | 21:00–21:29 | 21:05 通知 → 21:20 打刻 |

**重要**: 許容範囲を1秒でも外れると会社から確認連絡が来るため、スクリプトは範囲の内側だけで押し、
終端手前 `--safety-sec` 秒でも締め切る。範囲外・不確実な場合は押さず通知する（ベストエフォート）。

## スケジュール（cronはUTC。JST=UTC+9）
| 対象 | 起動(JST) | 打刻締切(JST) | cron(UTC) |
|---|---|---|---|
| A 出発 (08:30) | 06:42 | 07:10 | `42 21 * * *` |
| A 上番 (08:30) | 08:05 | 08:22 | `5 23 * * *` |
| A 下番 (17:15) | 17:14 | 17:25 | `14 8 * * *` |
| B 出発 (15:00) | 13:30 | 13:52 | `30 4 * * *` |
| B 上番 (15:00) | 14:30 | 14:52 | `30 5 * * *` |
| B 下番 (21:00) | 21:05 | 21:20 | `5 12 * * *` |

`ShiftMax A出発2`（07:12 起動）は 1 回目の予備として作成したが、見送り指示を二度出す必要が生じるため
一時停止中。1 回目が打刻できなかった日に復活させる想定。

各トリガーは毎日発火し、スクリプトが「今日が該当パターンの勤務日か」を判定して、
該当しなければ何もしない（SKIP_NO_MATCH）。便利URLはリポジトリには保存せず、トリガー設定側に置く。

### 運用上の注意
- トリガーは毎回新しい無人セッションで動くため、セッション側の判断で実行を見送ることがある
  （2026-08-29 の A 出発で発生）。その場合も理由が通知されるので、本人が手動で打刻する。
- 各トリガーのプロンプト冒頭に、スクリプトが行う 3 段確認（対象行の実在・許容範囲・打刻済み判定）と
  本人公認である旨を明記して、同じ誤解による見送りを減らしている。
