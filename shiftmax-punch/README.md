# ShiftMax 勤怠自動打刻

ShiftMax（勤怠報告一覧）の「出発 / 上番 / 下番」リンクを、指定の許容時間内に自動で押す仕組み。

## 構成
- `punch.mjs` … 一覧ページを読み、対象リンクと表示時刻を解析し、許容時間内なら打刻する Node スクリプト（依存なし・要 `curl`）。

## スクリプトの使い方
```bash
SHIFTMAX_URL='<便利URL WorkTimeListForStaff.aspx>' \
node punch.mjs --action 出発 --expect 08:30 --window 06:30-07:29 [--dry-run]
```
- `--action` 押す対象（出発 / 上番 / 下番）
- `--expect` その行に表示される時刻（例 08:30）。パターン取り違え防止用。
- `--window` 押してよい許容範囲（JST, `HH:MM-HH:MM`）。範囲外なら**絶対に押さない**。
- `--dry-run` 実際には押さず、判定結果だけ出力。
- `--safety-sec` 終端手前の安全マージン秒（既定20秒）。

### 結果(RESULT)
| RESULT | 意味 |
|---|---|
| SUCCESS | 打刻して「◯◯報告完了」を確認 |
| SKIP_NO_MATCH | 対象リンクなし（休み/打刻済み/別パターン）→ 何もしない |
| SKIP_OUT_OF_WINDOW | 許容範囲外 → 誤打刻回避のため押さない（要手動） |
| SESSION_EXPIRED | 便利URLの有効期限切れの可能性 |
| ERROR / UNCERTAIN | 通信失敗など → 要手動確認 |

## 打刻ルール
勤務は不定期（水曜・祝日は無し。毎月シフト割当）。毎朝ページを読み、勤務日なら A/B いずれかのパターンになる。

実行は 2 系統に分かれている。

- **出発・上番** … GitHub Actions（`github-actions-punch.yml` 参照）。判断の余地なくスクリプトを回す。
  成功しても通知はなく、ERROR / SESSION_EXPIRED / UNCERTAIN のときだけジョブが落ちてメールが届く。
- **下番** … Claude のルーチン。`--dry-run` で対象日か判定し、対象なら本人に通知して締切まで待つ。
  締切までに見送り指示（「残業」など）が届けば押さない。残業で退勤時刻が動くのは下番だけなので、
  この猶予が要るのも下番だけ。

対象日でなければどちらも通知も打刻もしない。

### Aパターン（出発・上番の表示が 08:30）
| 操作 | 許容範囲(JST) | 実行 |
|---|---|---|
| 出発 | 06:30–07:29 | Actions が 06:32/06:47/07:02/07:17 に試行 |
| 上番 | 08:15–08:29 | Actions が 08:07〜08:25 に 5 回試行 |
| 下番 | 17:15–17:29 | ルーチンが 17:14 通知 → 17:25 打刻（残業なら見送り） |

### Bパターン（出発・上番の表示が 15:00）
| 操作 | 許容範囲(JST) | 実行 |
|---|---|---|
| 出発 | 13:45–13:59 | Actions が 13:37〜13:55 に 5 回試行 |
| 上番 | 14:45–14:59 | Actions が 14:37〜14:55 に 5 回試行 |
| 下番 | 21:00–21:29 | ルーチンが 21:05 通知 → 21:20 打刻 |

**重要**: 許容範囲を1秒でも外れると会社から確認連絡が来るため、スクリプトは範囲の内側だけで押し、
終端手前 `--safety-sec` 秒でも締め切る。範囲外・不確実な場合は押さず通知する（ベストエフォート）。

## スケジュール
出発・上番の cron は `github-actions-punch.yml` を参照（UTC。JST=UTC+9）。
GitHub の定期実行は数分〜十数分ずれるため、各打刻を許容範囲の前後で複数回試す。
スクリプトは範囲外・対象なし・打刻済みのいずれでも何もしないので、重複実行は無害。

下番のルーチン（Claude 側、有効なのはこの 2 件だけ）:

| 対象 | 起動(JST) | 打刻締切(JST) | cron(UTC) |
|---|---|---|---|
| A 下番 (17:15) | 17:14 | 17:25 | `14 8 * * *` |
| B 下番 (21:00) | 21:05 | 21:20 | `5 12 * * *` |

出発・上番のルーチン（`ShiftMax A出発` / `A出発2` / `A上番` / `B出発` / `B上番`）は
GitHub Actions と二重になるため一時停止済み。設定は残してあるので、Actions を止めれば戻せる。

便利URLはリポジトリには保存せず、GitHub の Secret（`SHIFTMAX_URL`）とルーチン設定側に置く。

### 運用上の注意
- 出発・上番をルーチンから Actions に移した経緯: 無人セッションが「本人の行動と紐付かない
  タイムスタンプの自動送信は避けるべき」と判断して実行を見送る事象が 2026-08-29 / 09-27 に発生した。
  プロンプト冒頭に前提（スクリプトが行う 3 段確認、本人公認である旨）を書いても再発したため、
  モデルの判断を挟まない実行経路に移した。下番は猶予つき通知が要るのでルーチンのまま。
- GitHub は 60 日間リポジトリに更新がないとスケジュール実行を自動停止する。停止時はメールが届くので
  Actions タブから再開する。
